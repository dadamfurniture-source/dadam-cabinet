# 주방가전 모델 수집기

사장님 요청 (2026-10-25): "전자레인지 및 주방가전 데이터 수집".
품목은 전자레인지 · 광파오븐, 빌트인 오븐 · 식기세척기, 쿡탑 · 후드, 밥솥(새 종류)이다.
브랜드는 삼성 · LG 먼저 모은다. 두 회사가 밥솥을 팔지 않아 **밥솥만 쿠첸 · 쿠쿠**에서 모은다.

냉장고 수집기(`../fridge-catalog`)의 공용 부분을 그대로 불러 쓴다: `Fetcher`(robots.txt · 1.2초 간격 · `cache/` · `--offline`), 삼성 · LG 목록과 사양 API, 이름 정리 · 정수 변환. 냉장고 수집기 파일은 고치지 않는다.

## 어디서 가져오나

| 브랜드 | 메뉴 (목록) | 치수 | 그 밖 |
|---|---|---|---|
| 삼성 | `goodsList` — 전자레인지 `100034611` · 큐커 멀티/오븐 `100044008` · 식기세척기 `36080000` · 인덕션 `36070000` · 후드 `100027453` (카테고리 페이지 HTML 의 `dispClsfNo`) | `compGoodsSpecList` — 아래 칸 이름 | 오븐 '타공' = 설치 공간(니치) W×H×D, 인덕션 '타공 사이즈' = 상판 타공 W×D |
| LG | `plp/category/{id}/model` — 광파오븐/전자레인지 `CT50019018` · 식기세척기 `CT50000086` · 전기레인지 `CT50000076` (본 사이트에 후드 메뉴 없음) | `pdp/models/{id}/spec` `제품 크기 (WXHXD,mm)` | 전기레인지 `싱크대 타공치수 (W X H X D)` → 타공 W · D, 전자레인지 · 광파오븐 `설치환경` → 위 · 옆 · 뒤 여유 |
| 쿠첸 | `cuchenmall.co.kr/sitemap-geo.xml` 의 상품 페이지 136개 중 이름에 '밥솥'(묶음 · 부품 제외) | '기본사양 · 사이즈' (`298(W)*408(D)*307(H)(mm)`) | 모델 코드 = 이름 다음 줄 판매 코드 |
| 쿠쿠 | `cuckoo.co.kr` **홈 화면에 걸린 상품 페이지만** — 상품 목록 API(`/rest/mall/mallProductSearch`)는 robots.txt 가 `/rest/` 를 막아 쓰지 않는다. 사이트맵 없음 | 상품정보고시 `크기(길이,폭,높이)` (길이 = 깊이). 없으면 '핵심 사양' 요약 글 (미검증) | |

- 칸 순서는 사양 이름에서 읽는다 (`가로 × 높이 × 깊이` · `WxHxD` …). 삼성 '외부 치수'(인덕션 · 후드)는 이름이 없어 가로 × 깊이 × 높이로 읽는다 — 인덕션 `600 x 520 x 50`.
- 종류는 제조사 메뉴가 정한다 (전자레인지 · 광파오븐 메뉴 → `microwave`). 삼성 '큐커 멀티/오븐' 메뉴만 사양의 설치 방식으로 나눈다: 빌트인 → `oven`, 프리스탠딩(큐커) → `microwave` `combi`.
- 삼성 식기세척기 · 후드일체형 인덕션은 단품도 goodsTpCd 20 이라 냉장고 수집기처럼 빼지 않는다. 부속품 묶음(…+정수필터)은 본체 치수가 같아 한 행으로 합쳐진다.
- LG '세트' 하위 메뉴(식기세척기 + 인덕션 묶음)는 뺀다. 단품이 따로 있다.
- 크기가 같은 색상 변형은 한 행으로 묶고 모델 코드는 `model_codes` 에 모두 남긴다.
- 후드 높이가 범위(`405~755`)면 낮은 값을 넣고 원문은 비고에 남긴다 (`치수범위`).
- 다나와 등 가격비교 · 오픈마켓은 쓰지 않는다. 로그인 · 우회 없음, 한 번에 하나씩 1.2초 이상 간격.

## 순서

```bash
python -I collect.py --sample 3 --out sample          # 종류마다 몇 개씩
python -I collect.py --out kitchen                    # 전체 · 요청 약 530개 (12분쯤). 다시 돌릴 때는 --offline
python -I to_sql.py kitchen.json > import-kitchen.sql  # Supabase SQL 편집기에 붙여 넣을 파일
```

1. 처음 한 번은 `database/appliance-models-kitchen.sql` 을 Supabase 에서 실행한다 (밥솥 종류 · 종류별 세부 구분 · 타공 가져오기).
2. `import-kitchen.sql` 을 실행한다. 같은 브랜드에서 모델 코드가 겹치면 갱신하고, 없으면 추가한다. 여러 번 실행해도 중복이 생기지 않는다.
3. 관리자 → 가전 모델 관리에서 종류별로 훑어본다. ⚠ 표준(미검증) 행은 비고의 '확인 필요' 를 본다.

## 검증 표시 (`to_sql.py`)

| 태그 | 뜻 | |
|---|---|---|
| (없음) | 제조사 사양표 글자 | 검증 |
| `요약문` | 쿠쿠 '핵심 사양' 요약 글 — 폭 · 깊이가 뒤바뀐 곳이 있다 (트윈프레셔 6인용 'W383 x D262') | 미검증 |
| `고시불일치` | 쿠첸 판매 코드와 상품정보고시 코드가 다르다 (더 동글 4인용 CRE-D0401W · 고시 CRM-E0101W) — 판매 코드만 넣는다 | 미검증 |
| `치수순서추정` | 쿠첸 사이즈에 W · D · H 표시가 없다 — 표시한 곳의 순서(가로*깊이*높이)로 읽었다 | 미검증 |
| `치수순서의심` | 같은 브랜드 · 인분에서 세 치수는 ±2 로 같은데 넣은 순서가 다른 행들 (121 플러스 10인용 네이처 화이트 397(W)*301(D) · 블라썸화이트 301(W)*397(D)) | 미검증 |
| `치수확인필요` | 종류별 치수 범위(`collect.py BOUNDS`) 밖 — LG 포터블 인덕션 `300 x 410 x 40` (WxHxD 라 적혀 있으나 W×D×H) | SQL 에서 뺀다 |

## 주의

- 쿠쿠는 목록을 못 읽어 홈 화면에 걸린 상품(168개 중 밥솥 22)만이다 — 전체가 아니다. 그중 상품정보고시 크기가 있는 것이 적다.
- 쿠첸 상품 페이지는 색상마다 따로 있고 이름 · 치수 순서가 서로 어긋난 곳이 많다 (`치수순서의심` 19행). 밥솥장 검사에 쓰기 전에 사람이 한 번 확인한다.
- 삼성 식기세척기 사양에는 설치 공간(니치)이 없다 — 식기세척기 설치 가이드 글은 아직 읽지 않았다.
- LG SIGNATURE Kitchen Suite(빌트인 오븐 · 후드 · 쿡탑)와 데이코는 이번에 넣지 않았다 (`lge.co.kr/kr/business/sks`, `dacorkorea.com`).
- 제조사 사진 사용 약관 확인은 사장님 몫이다 — 수집기는 주소만 모은다.
