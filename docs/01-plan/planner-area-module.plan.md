# Plan: 배치 사각형 → 영역 + 모듈 추가 방식

> 근거 문서 — 이해 확인본 `docs/01-plan/planner-module-workflow.understanding.html`,
> 규칙 보관본 `docs/01-plan/autocalc-rules.md`.
> 기준 커밋 `6a3df64` · 작성 2026-08-16.

## 목표

구조 단계가 "배치에서 온 사각형 = 모듈" 을 그리던 것을,
**"사각형은 영역, 모듈은 그 안에 넣는 것"** 으로 바꾼다.

1. 구조 단계 첫 화면은 **영역만** 보인다 (모듈 0개)
2. 영역을 클릭하면 우측 상단에 **모듈 추가 / 제거**
3. 추가된 모듈은 W600 · H850 · D550 · 선반 1개
4. 모듈을 클릭하면 옵션 팔레트가 **아이콘**으로 뜨고, 아이콘을 누르면 팝업

## 확정된 전제

- **자동계산은 이번 범위 밖이다.** 앞으로 강화학습으로 대체되므로 지금은 규칙만
  `autocalc-rules.md` 에 보관했다. 기존 `autoCalcForSet` 경로는 **건드리지 않고 그대로 둔다.**
- 규칙 보관본의 "미해결 5건" 은 학습 이전에 사람이 정할 항목으로 남긴다.

## A1 — 영역과 모듈을 분리한다

**지금**: `loadModules()` 가 `dadam_layout_v1` 의 사각형을 그대로 모듈로 바꾼다.
**바꿀 것**: 사각형은 `areas` 로 읽고, `modules` 는 빈 배열로 시작한다.

### 데이터

배치 JSON 형식은 **바꾸지 않는다** (골든 3종이 이 형식을 입력으로 삼는다).
구조 단계에서만 해석을 달리한다.

```
layout.modules[]  →  areas[]      (영역 — 배경으로 그림, 편집 대상 아님)
structures 키     →  모듈 id      (새로 만든 모듈에 붙음)
```

모듈은 구조 단계가 소유하므로 저장 위치가 필요하다.
`dadam_structure_v1` 에 `modules` 배열을 같이 넣는다 (현재 `structures` 만 들어 있다).

### Q6 대응 (기본안, 답이 오면 조정)

기존 설계에 `modules` 가 없고 `structures` 가 있으면 **예전 방식으로 읽는다.**
새 설계는 빈 상태로 시작한다. 열자마자 설계가 사라지는 일을 막는 쪽을 기본으로 둔다.

### 검증
- 영역만 있는 상태에서 정면도·3D 가 오류 없이 뜬다
- 기존 저장 설계를 열면 모듈이 그대로 보인다
- 골든 3종 무변경

## A2 — 영역 클릭 → 모듈 추가 / 제거

영역을 클릭하면 화면 우측 상단에 버튼 두 개를 띄운다.
정면도의 영역 사각형과 3D 양쪽에서 선택할 수 있어야 한다
(모듈 클릭이 `setActiveModule` 한 곳으로 모였듯, 영역도 `setActiveArea` 하나로 모은다).

- **모듈 추가** — 영역 안 빈 자리 왼쪽부터 A3 의 기본 모듈을 놓는다
- **모듈 제거** — 선택된 모듈을 지운다. 선택이 없으면 비활성

### Q4 · Q5 대응 (기본안)

- 넘치면 **추가를 막고 토스트로 남은 폭을 알린다.** 값을 임의로 줄이지 않는다
  (지어낸 치수를 남기지 않는다는 기존 원칙)
- 영역의 섹션과 **같은 섹션 모듈만** 넣는다. 다른 섹션은 답을 받은 뒤 연다

### 검증
- 영역 W2400 에 W600 모듈 4개가 들어가고 5개째는 거부된다
- 추가·제거가 정면도·3D·우측 패널에 모두 반영된다

## A3 — 새 모듈 기본값 — **Q1 확정 후 착수**

W600 · H850 · D550 · 선반 1개.

### 이미 확인된 것

| 항목 | 현재 규칙이 내는 값 | 판정 |
|---|---|---|
| 도어 | W600 → 1장 (350–600 안) | 요청과 일치 |
| 선반 | H850 → 1개, 바닥 350mm | **요청과 일치 — 새 규칙 불필요** |

선반 1개는 `calcDefaultShelves` 의 간격 규칙(300–450)이 이미 내는 결과다.
상수를 새로 만들지 않는다.

### Q1 별 갈래

| 답 | H | 상판 | 몸통 | 할 일 |
|---|---|---|---|---|
| ① 700 = 몸통만 | 862 | 12 | 700 | 기본 H 를 862 로. 850 은 성립하지 않는다 |
| ② 700 = 몸통 688 + 상판 12 | 850 | 12 | 688 | 그대로. **엔진의 선반 계산에 상판을 반영해야 한다** |
| ③ 상판 없음 | 850 | 0 | 700 | 그대로. 하부장에 상판 없는 예외를 명시 |

②를 택하면 규칙 보관본 9장의 "상판 12mm" 미해결 항목이 같이 닫힌다.

### 검증
- 새 모듈의 `전체 = 부위 합 + 몸통` 이 팔레트 한 줄과 3D 실측에서 모두 맞는다
- 선반 1개가 몸통 안에 놓인다

## A4 — 팔레트를 아이콘 + 팝업으로

지금 팔레트는 라벨 + 입력칸을 세로로 나열한다. 항목이 11개라 스크롤이 생겼다.
아이콘 격자로 바꾸고, 아이콘을 누르면 그 항목만 담은 팝업을 연다.

### 아이콘 (이해 확인본과 동일)

크기 · 다리발 · 상판 · 상하 구성 · 도어 갯수 · 도어 방향 · 선반 · 서랍 단수 · 손잡이 · 모듈 고정.
좌대·상몰딩은 키큰장·냉장고장에서만 — 지금 팔레트가 섹션에 따라 칸을 감추는 규칙을 그대로 쓴다.

### 지켜야 할 것

- **양문 셀은 방향을 묻지 않는다.** `#471` 에서 고친 규칙이 팝업에도 그대로 적용된다
- 높이 부위 4종은 **몸통 50mm 미만이면 되돌린다** — 우측 패널과 같은 기준
- 값 변경 시 저장 + 정면도 + 우측 패널 + 3D 갱신 (현재 `commit()` 과 동일)

### 검증
- 아이콘 10종이 뜨고, 누르면 해당 팝업이 열린다
- 팝업에서 바꾼 값이 저장되고 3D 까지 반영된다
- **표시 검사와 반영 검사를 나눈다** — 이 저장소는 "보이지만 동작 안 하는 컨트롤" 을
  세 번 만들었다 (`#471` 방향, `#472` 다리발, `#473` 상판·좌대)

## 핵심 파일

### 수정
- `mockup-structure.html`
  - `loadModules()` → 영역 로딩 + 모듈 빈 시작 (A1)
  - `setActiveArea()` · 모듈 추가/제거 버튼 (A2)
  - `renderFrontView` · `renderAll3D` — 영역을 배경으로 그리는 경로 (A1)
  - `renderModulePalette()` → 아이콘 격자 + 팝업 (A4)
- `js/planner/planner-engine.js` — 새 모듈 기본 구조 생성 (A3, Q1 확정 후)

### 건드리지 않는 것
- `autoCalcForSet` · `distributeModules` · `calcDefaultShelves` — 자동계산 경로
- 배치 JSON 형식 — 골든 3종의 입력
- `mockup-shell.html` — 배치 단계는 그대로

## 영향 / 위험

| 위험 | 영향 | 대응 |
|---|---|---|
| 기존 설계가 빈 화면이 된다 | 사용자 데이터 손실처럼 보인다 | A1 에서 구형 데이터는 예전 방식으로 읽는다 |
| 골든이 깨진다 | 브리지 계약 파손 | 배치 JSON 형식을 바꾸지 않는다. 매 단계 골든 확인 |
| 영역/모듈 이중 상태 | 어느 쪽이 정본인지 흐려진다 | 영역은 **읽기 전용**. 편집 대상은 모듈뿐 |
| 팔레트 회귀 | 팝업이 값을 안 넘긴다 | 표시/반영 검사 분리 + 가드 실증 |
| 자동계산과 충돌 | 모듈을 손으로 넣었는데 자동계산이 덮는다 | `isFixed` 보존 규칙이 이미 있다. A2 에서 새 모듈에 적용할지 결정 |

## 검증 (전 단계 공통)

- 골든 스냅샷 3종 무변경 — 의도적 변경이면 **별도 커밋**으로 분리 (불변식 1)
- 추출과 원본 삭제는 같은 커밋 (불변식 4)
- 단계마다 신규 테스트. 가드가 실제로 잡는지 되돌려서 실증
- 3D 는 jsdom 에서 못 돌린다 → 정적 가드 + 브라우저 실측 병행
