배치 사각형 → 모듈을 넣는 방식으로

구조 단계가 “배치에서 온 사각형 = 모듈”을 그리던 것을, “사각형은 영역, 모듈은 그 안에 넣는 것”으로 바꾼다.

2026-08-16 · 기준 커밋 6a3df64 · 대상 mockup-shell.html · mockup-structure.html

01 무엇이 달라지나

항목지금요청
배치 사각형사각형 하나 = 모듈 하나사각형은 영역. 모듈을 담는 그릇
구조 단계 첫 화면배치의 사각형이 전부 모듈로 실려 있음사각형만 보임. 모듈 0개
모듈 만들기배치 단계에서만 가능사각형을 클릭 → 우측 상단 추가 / 제거
모듈 옵션라벨 + 입력칸이 세로로 나열아이콘을 먼저 보여주고, 누르면 팝업

지금은 loadModules()가 dadam_layout_v1의 사각형을 그대로 모듈로 바꾼다. 이 연결을 끊고, 사각형은 배경으로만 그리는 것이 이 변경의 핵심이다.

02 흐름

  1. 배치 단계에서 사각형을 만든다지금과 같다. 바뀌는 것 없음.
  2. 구조 단계로 넘어간다사각형만 그려진다. 모듈은 하나도 없는 빈 상태로 시작.
  3. 사각형을 클릭한다화면 우측 상단에 모듈 추가 · 모듈 제거 버튼이 나타난다.
  4. 모듈을 추가한다W600 · H850 · D550 · 선반 1개 짜리 모듈이 생긴다.
  5. 모듈을 클릭한다옵션 팔레트가 아이콘으로 뜬다. 아이콘을 누르면 그 옵션의 팝업이 열린다.

05 착수 전에 정해야 하는 것

충돌H850의 700은 무엇인가

말씀하신 850 = 모듈 700 + 다리발 150 에는 상판이 없다. 그런데 코드 안에는 서로 다른 두 모델이 이미 공존하고 있고, 요청값은 그중 엔진 쪽과 정확히 일치한다.

높이 패널 · data-constants.js:43 850 = 다리발 150 + 몸통 688 + 상판 12 자동계산 엔진 · autoCalcModule 선반 계산에 쓰는 몸통 = 850 - 150 - 0 = 700 (상판을 빼지 않는다)

즉 “모듈 700”은 엔진이 지금 쓰는 값이다. 두 모델의 차이는 딱 상판 12mm.

여쭙습니다 ① 700이 몸통만이고 상판은 따로 붙는가 (그러면 전체는 862가 된다)
② 700이 몸통 688 + 상판 12를 합친 값인가 (그러면 850이 맞고 코드 모델과도 맞다)
③ 이 모듈에는 상판이 아예 없는가
충돌기본 높이 850인가 870인가

배치 단계의 하부장 기본 높이는 870이다(PLANNER_SECTIONS.lower.moduleH). 새 모듈을 850으로 만들면 배치 사각형과 그 안의 모듈이 서로 다른 높이가 된다.

여쭙습니다 850으로 통일해서 배치 기본값도 바꾸는지, 아니면 사각형 870 · 모듈 850으로 다르게 두는 것이 의도인지.
확인깊이 550

하부장 배치 기본 깊이는 650, 냉장고장이 550이다. 요청하신 550이 하부장의 새 기준인지, 이번 모듈에만 해당하는지.

확인영역과 모듈의 관계

사각형이 영역이 되면 그 안에서 지켜야 할 규칙이 생긴다.

  • 영역 W2400에 W600 모듈을 넣으면 4개에 딱 맞는다. 5개째를 넣으면 넘치게 두는지, 막는지, 폭을 줄이는지.
  • 하부장 영역에 상부장 모듈을 넣을 수 있는지.
  • 모듈은 왼쪽부터 차곡차곡 붙는지, 아니면 자유롭게 놓는지.
확인자동계산과 역할이 겹친다

지금 autoCalcForSet은 “큰 모듈 하나를 셀로 쪼개는” 방식이다. 모듈을 직접 추가하게 되면 이 역할과 겹친다.

여쭙습니다 자동계산이 영역을 W600 모듈 여러 개로 채우는 쪽으로 바뀌는 것이 맞는지. 그러면 셀 분할(distributeModules)은 모듈 하나 안의 도어 분할로만 남는다.
확인이미 저장된 설계

구조 단계가 모듈 0개로 시작하면, 지금까지 저장해 둔 설계를 열었을 때도 빈 화면이 된다.

여쭙습니다 기존 설계는 예전처럼 모듈이 실려 보이게 할지, 아니면 새 방식으로 통일할지.

06 손대야 하는 곳

  • mockup-structure.html · loadModules() — 사각형을 모듈로 바꾸는 연결을 끊고, 영역으로만 그린다
  • mockup-structure.html · renderFrontView / renderAll3D — 영역 사각형을 배경으로 그리는 경로 신설
  • mockup-structure.html · renderModulePalette() — 세로 나열을 아이콘 격자 + 팝업으로 교체
  • js/planner/planner-engine.js — 새 모듈의 기본 구조를 만드는 함수 (H850 해석이 정해진 뒤)
  • __tests__/planner-module-palette.test.js — 아이콘·팝업 구조에 맞게 갱신

골든 3종(test-utils/planner-golden.js)은 배치 JSON을 입력으로 삼는다. 배치 형식이 그대로면 골든은 유지되고, 영역 개념이 배치 JSON에 새 필드로 들어가면 골든 갱신이 필요하다.

이 문서는 제가 이해한 내용이고 아직 코드는 건드리지 않았다. 위 여섯 가지 중 특히 H850의 700이 정해져야 나머지가 따라 정해진다.
