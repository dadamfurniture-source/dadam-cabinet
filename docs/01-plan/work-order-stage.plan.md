## 0. 한 문단 요약

작업지시서는 **이미 있다** — `workers/workflow-api` 가 서버에서 그리는 「작업지시서 v2」 (표지·키팅·시트별 재단표·철물·
보링·조립 체크·rev 차이·QR 라벨, 8섹션). 문제는 세 가지다.
① **안 보인다.** 플래너 → BOM(Step 3) 으로 넘어온 뒤, BOM 표 아래 「업무 루프」 패널에서 *동결 → 발행 → 인쇄* 버튼을
순서대로 눌러야 나온다. 단계도, 다음 버튼도 없다.
② **공장과 안 맞는다.** 도어는 외주(상일)인데 도어 원판이 자체 재단표에 섞여 있고, 보링 공정은 없는데 조립 체크에
「보링 ☐」 이 있다. 섹션은 *문서 구성* 기준이지 *사람* 기준이 아니다 — 재단 기사·엣지 알바·조립 기사가 각자 자기
종이만 뽑을 수 없다.
③ **치수 정면도가 없다.** 표지에 3D 렌더 PNG 만 있다. 이 도메인에서 가장 잘 읽히는 그림(통 폭·단 높이가 mm 로 적힌 정면도)이 빠졌다.

그래서 새 4단계 「작업지시서」 는 이렇게 간다: **BOM 아래 `작업지시서 →` 한 번 → 저장·동결·발행이 자동으로 이어지고 →
사람별 꾸러미 5장(재단·엣지 · 조립 · 도어 발주 · 라벨 · 설치)을 카드로 고른다.** 문서는 여전히 `work_order` 하나다 —
꾸러미는 같은 동결 문서를 섹션만 골라 찍는 인쇄 옵션(`/print?pack=`)이다. 치수 정면도는 서버가 동결된
`design_payload` 로 직접 그린다(SVG) — 그래서 그림과 자재표가 늘 같은 rev 다.

## 4. 설계 [결정]

### 4.1 셸 4단계 「작업지시서」 (Design UI 도메인)

- `detaildesign.html` 스테퍼에 `step-dot-4` 와 `#step4-content` 를 더한다. `ui-step1.js` 에 `goToStep4()` / `backToStep3()` (`:294-346` 패턴).
- Step3 BOM 하단에 고정 버튼 `작업지시서 →`. 플래너 iframe 단계(`PLANNER_STAGES`)는 **건드리지 않는다** — 작업지시서는 스냅샷·문서 기반이라 `planner_snapshots` 단계가 아니다.
- `#workflowPanel` 의 제작·설치 작업지시서 버튼은 Step4 로 옮긴다. 고객확인서·수주 전환은 Step3 에 남긴다 (고객 쪽 일).
- Step4 화면 구성:
  1. **상태 카드** — 설계 저장 여부 · 동결 rev · 최신 발행 문서번호(`DD-…-WO-rN`) · stale 여부 · 고객 승인 여부.
  2. **[발행]** 한 버튼 — 아래 4.2 연쇄.
  3. **꾸러미 카드 5장** — 각 카드에 대상(사람), 쪽수, 예상 시간, [인쇄].
  4. **발행 이력** — rev 목록, 이전 rev 와 차이 개수(⑦ 요약).
- 구조 단계 `#nextBtn` 라벨을 실제 동작에 맞춰 `BOM 산출 →` 로 (Planner 도메인, 한 줄).

### 4.2 [발행] 연쇄 — 버튼 하나 (Design UI 도메인, `workflow-client.js`)

```
설계 저장됨?  ─아니오→ persistence 저장 (currentDesignId 확보)
    │예
스냅샷 POST /designs/:id/snapshots {design, bom, hardware, cutPlan}
    │ 같은 content_hash 면 200 (재사용) — 새 rev 가 생기지 않는다
이 스냅샷의 유효한 work_order 가 있나? (GET /designs/:id/documents)
    │있음 → 그 문서를 쓴다 (중복 발행 금지)
    │없음 → POST /snapshots/:sid/documents {doc_type:'work_order'}
    ▼
꾸러미 카드 활성
```

- 설치 작업지시서는 현장 정보가 있을 때만 같이 발행 (없으면 카드에 "현장 정보 입력" 링크).
- **발행 시점 규칙 [확인 필요 Q6]**: 권장안은 *미리보기는 언제나, 확정 발행은 고객확인서 승인 뒤* (승인 없이 발행하려면 사유 입력).

### 4.3 꾸러미 = 같은 문서, 섹션만 골라 찍기 (Workflow Worker 도메인)

`GET /documents/:id/print?pack=<key>` — `renderWorkOrder(ctx, {pack})` 가 섹션을 고른다. **동결 payload 는 하나**라서
꾸러미끼리 숫자가 어긋날 수 없다. `pack` 이 없으면 지금처럼 전체.

| pack | 받는 사람 | 담는 섹션 | 머리 숫자 |
|---|---|---|---|
| `cut` | 재단 기사 | **재단·엣지 지시서** (③ 재단표 + ⑨ 엣지 통합, 아래 4.3.1): 표지(정면도) · 시트별 배치도에 엣지 변 표시 · 부재 표에 엣지 변·두께·코드 · 소부품 · 미배치 · 끝장에 엣지 롤 합계 — **PB·뒷판 그룹만** | 원판 n장 · 재단 약 n×7분 · 엣지 약 n×15분 · 엣지 0.6 / 1.0 m |
| `assembly` | 조립 기사 | ② 키팅 · ④ 철물 · ⑥ 조립 체크(새 칸) · **⑪ 모듈 치수도** | 통 n · 서랍 n · 도어 n짝 · 약 (통+서랍)×12 + 도어×1 + 통×5 분 |
| `door` | 도어 외주처 (상일) | **⑩ 도어 발주서** (신설): partId · 가로×세로×18 · 마감 코드 · 발주 코드(`vendor_code`) · 스와치 · 수량 · 엣지 1.0 4면 · 경첩 컵 위치(⑤ 에서 옮김) · 경첩 방향 | 도어 원장 n장 · 도어 n짝 · **금액 없음** |
| `labels` | 재단 기사 (재단 직후 부착) | ⑧ QR 라벨 | 라벨 n장 / A4 n쪽 |
| `all` | 사무실 보관 | ①~⑪ 전부 | — |

- 설치는 이미 별도 문서(`installation_order`)다 — Step4 의 5번째 카드로 그 문서 인쇄를 건다.
- ⑥ 체크 칸: `재단 ☐ 엣지 ☐ 조립 ☐ 도어 달기 ☐ 서랍 ☐ 검수·포장 ☐` + 완료일 · 서명. 서랍 없는 모듈은 서랍 칸 빗금.
- 표준시간은 워커 상수 `src/labor-standards.js` 한 곳 (2026-10-12/13 확정 가정 값). 발행 시 `render_payload.labor` 로 동결 — 상수를 고쳐도 이미 낸 문서는 안 바뀐다.

**불변식 (시험으로 묶는다):** `cut` 꾸러미 부재 + `door` 꾸러미 부재 = BOM 전체 부재 (`partId#k` 기준, 빠짐·겹침 0).
재단 배치와 자재표가 어긋나 어느 시트·소부품·미배치에도 없는 사내 부재는 재단 꾸러미 끝에 「배치에 없는 부재」 로 따로 싣는다 (PR 1 구현 중 발견).

#### 4.3.1 재단·엣지 지시서 — 재단 꾸러미 하나로 [결정, 2026-10-13 사장님]

> "실제 엣지 표시 작업은 재단사가 하니까 재단 지시서와 엣지 목록을 통합해서 만들어줘."

재단 기사가 부재를 잘라 내면서 **붙일 변을 부재에 표시**하고, 알바는 그 표시대로 엣지를 붙인다. 그래서 엣지 정보는
따로 떼지 않고 **재단 순서 그대로** 재단 종이에 싣는다. 별도 `edge` 꾸러미는 없다.

시트 한 장 = 한 쪽:

```
┌ 시트 3 / 6 · PB 15T · 1220×2440 · 수율 82% ───────── 재단 ☐  엣지 표시 ☐ ┐
│  배치도 (축소 SVG)                                                      │
│   ┌───────┬────┐   굵은 실선 = 엣지 0.6                                  │
│   │ L2-측판 ┃    │   굵은 이중선 = 엣지 1.0                               │
│   ┝━━━━━━━┥    │   선 없음 = 엣지 없음                                    │
│   └───────┴────┘   (흑백 인쇄에서도 구분되게 색이 아니라 선 모양으로)        │
├─────────────────────────────────────────────────────────────────────────┤
│ 라벨# │ partId      │ 부재      │ 가로×세로 │ 회전 │ 엣지 변 L R T B │ 두께 · 코드  │
│  14   │ 0-l2-side-0 │ 측판(좌)  │ 564×720  │      │ □ □ ■ □        │ 0.6 · WHT   │
└─────────────────────────────────────────────────────────────────────────┘
```

- 엣지 변은 BOM 행의 `edges{L,R,T,B}` 를 그대로 쓴다 (새 계산 없음). 회전(`rot`)된 부재는 배치도 위의 변을 **부재 기준**으로 돌려 그린다 — 표의 L R T B 는 늘 부재 기준.
- 마지막 쪽 **엣지 합계**: 두께(0.6/1.0) × 엣지 코드별 길이(m) · 부재 수 · 필요한 롤 수 — 알바가 롤을 미리 챙기는 용도. 이 꾸러미 안에 둔다.
- 시트 머리 체크 칸 `재단 ☐ 엣지 표시 ☐` — 각자 자기 작업을 스스로 검수하는 공장 방식에 맞춘다.
- QR 라벨(⑧)에도 작은 엣지 변 도식을 넣는다 — 라벨을 붙인 부재만 들고 가도 붙일 변이 보인다.
- 머리 숫자: 재단 시간(원판 × 7분)과 엣지 시간(PB 원판 × 15분)을 **따로** 적는다 — 하는 사람이 다르다.

### 4.4 치수 정면도 — 서버가 동결 설계로 그린다 (Workflow Worker 도메인)

- 새 파일 `src/templates/elevation.js`: `design_payload.items[].modules[]` → 품목마다 **정면도 SVG** (인라인, 축척 1 mm = 일정 px).
  - 하부 줄 · 상부 줄 · 키큰장(두 줄 걸침), 통마다 번호(⑥ 의 모듈 이름과 같은 번호), 도어 분할선, 서랍 단.
  - 치수: 통 폭 사슬(아래) · 전체 폭 · 하부 높이 · 상부 높이 · 상판·받침 · 상하부 사이.
  - **검증**: 통 폭 사슬 합 = 품목 W, 어긋나면 그 자리에 빨간 "합 불일치 Δmm" (그림이 BOM 을 숨기지 않게).
- ① 표지: 정면도 SVG(주) + 3D 정면 렌더 PNG(참고, 있으면).
- ⑪ 모듈 치수도: 모듈 하나씩 W×H×D, 측판·바닥·상판·뒷판 위치와 두께 — 조립 기사용.
- 플래너에서 SVG 를 직렬화해 올리는 길은 **택하지 않는다**: 편집 화면 DOM(눈금자는 HTML 오버레이)이라 떼어 내기 어렵고,
  올린 그림과 동결 BOM 의 rev 가 갈릴 수 있다. 서버 생성은 저장소 스키마(`design_renders.kind` CHECK)도 안 건드린다.
- 모듈 순서: `exportDesign()` 은 `item.modules` 를 그대로 복사한다 (`config-constants.js:92`). 좌→우 순서 · `x` 보유 여부는
  구현 첫날 실제 설계 3종으로 확인한다. ㄱ자·코너는 **벽별로 펼친 정면도** + 코너 표식 [확인 필요 Q4].

**PR 2 구현 메모 (2026-10-13):** `src/templates/elevation.js`. 가로 위치는 브리지가 싣는 `_x`(배치 좌표 왼쪽 끝)를 쓰고,
`_x` 가 없거나 줄 안에서 겹치면(코너·다른 벽) 순서대로 붙이고 안내한다. 세로는 하부·키큰장·붙박이장은 바닥에서,
상부장은 천장(`item.h`)에 매단다 — 브리지가 플래너의 세로 좌표를 넘기지 않기 때문이다. 상부장이 천장에서 떨어진
설계는 그림이 실제와 다를 수 있다 → 후속: 브리지(Design UI)가 `_y` 를 싣게 한다. 검증 경고(빨강): 폭 초과,
위치 없을 때 하부 폭 합 ≠ 품목 폭, 상부가 하부를 파고듦. 모듈 번호 = `item.modules` 순번 — 모듈 명세·⑥·⑪ 에 같은 번호.

## 6. 판정 — 끝났다고 말하는 기준

1. 표준 3종 설계로 **플래너 → BOM → 작업지시서 발행까지 클릭 3번 이내** (BOM 산출 · 작업지시서 → · 발행).
2. 같은 설계를 두 번 발행해도 rev 가 늘지 않는다. 구조를 바꾸면 이전 문서에 stale 뱃지, 새 발행에 ⑦ 차이가 뜬다.
3. 부재 보존: `cut ∪ door` = BOM 전체, 겹침 0. 도어 원장 수 = 도어 그룹 시트 수. 재단·엣지 지시서의 엣지 합계(0.6 · 1.0 m) = BOM `edgeBanding` 중 PB·뒷판 몫, 회전 부재의 변 표시가 부재 기준과 같다.
4. 정면도 폭 사슬 합 = 품목 W (3종 모두), 불일치 표시는 고의로 깨뜨린 시험 설계에서만 뜬다.
5. 어떤 꾸러미에도 금액 문자열(`원`, `₩`, 단가 키)이 없다 — 시험으로 검사.
6. 사장님이 실제 A4 로 뽑아 재단 기사·조립 기사에게 한 번 건네 본다 — **공장 검토 통과**가 마지막 판정 (기존 계획 B5 완료 기준과 같음).
