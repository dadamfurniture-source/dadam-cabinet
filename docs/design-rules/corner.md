# 코너 구조 규칙 (ㄱ자 / ㄷ자)

## 1. 레이아웃 구조

| 레이아웃 | 코드 | Line 수 | 코너 수 |
|---------|------|---------|--------|
| ㅡ자형 | `I` | 1 (prime) | 0 |
| ㄱ자형 | `L` | 2 (prime + secondary) | 1 |
| ㄷ자형 | `U` | 3 (prime + secondary + tertiary) | 2 |

## 2. Line 정의

| Line | 역할 | 기본 W |
|------|------|--------|
| Prime | 주벽면 (기준선) | 사용자 입력 |
| Secondary | 코너에서 분기되는 첫 번째 벽면 | **1800mm** |
| Tertiary | Secondary 끝에서 분기되는 세 번째 벽면 (U형만) | **1800mm** |

- 하부장/상부장 모두 Secondary W 기본값 = **1800mm**
- Tertiary W 기본값 = Secondary W 또는 1800mm

### 2.1 라인이 두 경로에서 다르다 (2026-09-01 확정)

같은 "라인" 이 두 곳에서 다른 것을 가리킨다. 섞으면 도어 폭이 어긋난다.

| | detaildesign (네이티브) | 플래너 (배치·구조) |
|---|---|---|
| 라인이란 | `prime` / `secondary` / `tertiary` 선언 | **배치 공간** (`area`) |
| 벽면 하나에 | 라인 하나 | 배치 공간을 **여러 개 둘 수 있다** |
| 라인 W | `specs.lowerSecondaryW` 같은 입력 | 그린 사각형의 `area.W` |

**플래너에서는 `배치 공간 = 라인` 이다.** 한 벽면을 배치 공간 둘로 쪼개 그리면
그 벽면에 라인이 둘 있는 것이고, §3.4 의 도어 균등 분배도 **배치 공간 단위**로
돈다. 그래서 같은 벽면이라도 배치 공간이 다르면 도어 폭이 다를 수 있다 —
규칙대로다.

코너는 **실제로 맞닿은 배치 공간 하나**에만 걸린다. 같은 벽면의 다른 배치
공간은 코너와 무관하고 밀리지도 않는다.

> 회귀: `__tests__/planner-corner-blind.test.js` — "한 벽면에 배치 공간이
> 여러 개여도 된다" 6건.

## 3. 멍장 (Blind Corner Module) — 2026-07-17 규칙 확정

### 3.1 정의
멍장은 코너 교차 지점에 배치되는 모듈이다.
**"멍" = 교차하는 인접 라인에 의해 가려져 도어를 달 수 없는 구간**을 말하며,
멍장은 `멍 구간 + 도어 구간`으로 구성된 하나의 카카스다.

### 3.2 소속 라인 (사용자 결정)
- ㄱ자는 수직으로 회전된 어떤 형태든 가능
- 멍장은 **prime 또는 secondary 어느 라인에도 배치 가능** — 사용자 결정에 따른다
- 이하 공식에서 "인접 라인" = 멍장이 속하지 않은 쪽의 교차 라인

### 3.3 멍 공식 (하부장) — 2026-09-01 개정 (W12-54)

```
멍 W = 인접 라인 상판 깊이 − 10(물끊기) + 마감재(기본 60) + 목대 15
예:  650 − 10 + 60 + 15 = 715
예:  700 − 10 + 60 + 15 = 765
```

- **기준은 멍장을 가리는(수직으로 교차하는) 라인의 상판 깊이다.** 멍장이 속한
  라인이 아니라 그 앞을 가로지르는 쪽이다
- **물끊기 10**: 상판 끝에서 떨어지는 물이 도어에 닿지 않기 위한 여유
- **마감재 60**: 코너 접합부 — **몰딩 또는 휠라**. 이건 **자리**값이다.
  실제 부재는 **100** 으로 재단한다 (§3.3.1)
- **목대 15**: 멍장 도어 경첩을 달 목대 (15T). 멍 폭에 들어가고 BOM 부재로도
  나간다 (§3.5)

> 배치 공간 깊이 = 상판 깊이다. 그 깊이는 앞선에서부터
> `물끊기 + 도어 자리 + 몸통 깊이 + 여유(뒤)` 로 나뉜다 — 여유는 입력이 아니라
> 남는 값이다. 예) 700 = 10 + 20 + 550 + 120.
> 도어 **자재**는 18T 그대로이고, 20 은 시공 갭을 포함한 자리값이다.

> ⚠ 구버전 `멍 = 깊이 − 10 + 몰딩` (목대 없음)은 폐기. 확정 예시가 멍 700 →
> **715**, 멍장 1100 → **1110** 으로 바뀌었다.

#### 3.3.1 멍판 마감재 — 자리 60, 재단 100 (2026-09-02 확정, W12-61)

멍 공식의 `마감재 60` 은 **실제로 붙는 부재**이고, 자동으로 생성된다.
사람이 따로 붙이지 않는다.

- **위치**: 멍판(멍 구간)의 **도어 쪽 끝** — 멍장 도어 바로 옆.
  인접 라인의 도어 앞선과 멍장 도어 사이를 막는 조각이다
- **종류**: 멍장이 속한 **라인의 마감재를 따라간다**. 휠라를 고르면 휠라,
  몰딩을 고르면 몰딩. 라인 선택을 바꾸면 같이 바뀐다
- **재단 100 ≠ 자리 60**

```
자리 60   멍 공식에 들어가는 값. 폭 계산은 전부 이 값을 쓴다
재단 100  실제 부재 = 겹침 40 + 자리 60
```

마감재는 멍가림판 2.7T MDF 를 **덮고** 붙으므로 접착면 40 을 더 물어야 한다.
그래서 재단이 자리보다 넓다.

> ⚠ **100 을 공식에 넣지 말 것.** 멍 W · 멍장 W · 도어 폭 · 원장은 전부
> 자리 60 으로 계산한다. 재단 100 은 **BOM 산출과 화면 표현에만** 쓴다.
> 섞으면 멍장이 40 넓어져 원장이 깨진다.

라인 마감이 **없음**이어도 만든다 — 자리 60 은 이미 멍 폭에 들어가 있어서,
안 만들면 그 자리가 멍가림판 MDF 로 발주된다. 기본은 **휠라**다.
라인 좌·우 마감이 다르면 **멍장이 붙은 쪽 끝**을 따른다 (같은 시공 면).
EP 는 라인 측면을 감싸는 마감이라 코너 접합면에는 쓰지 않는다.

### 3.4 멍장 W — 도어 균등 분배 원칙

- 멍장의 코너 벽과 마주보는 측판은 **벽에서 50 이격** (여유공간)
- 멍장 도어 W는 **소속 라인 전체의 도어 균등 분배**로 결정된다
- **도어 최소 W = 350**
- 멍장 W = 멍 + 도어

예 (secondary 라인 1970, 인접 primeD 650, 좌측→코너 순서):

```
EP 20 + W790장(도어 395×2) + 멍장(도어 395 + 멍 715) + 여유공간 50 = 1970
→ 라인의 모든 도어 = 395 균등
→ 멍장 W = 715 + 395 = 1110
```

### 3.5 멍 구간 처리 / 내부 구조
- 멍 구간 정면: **2.7T MDF**로 가린다 (BOM 부재)
- 내부: **단일 수납 공간** (하부장 선반 기본), 하드웨어(회전 선반 등) 장착 가능

**멍가림판 재단 = 멍 W − 목대 15** (W12-61). 고정값이 아니다 — 인접 라인 상판
깊이에서 유도되므로 코너마다 다르고, ㄷ자에서는 두 멍이 서로 다른 라인을 보므로
둘이 다를 수 있다.

```
멍 W = 인접 D − 10 + 60 + 15
멍가림판 = 멍 W − 15 = 인접 D − 10 + 60      ← 인접 상판이 덮는 구간 + 마감재 자리
```

| 단 | 기준 | 멍 W | 멍가림판 | 보이는 MDF |
|----|------|------|----------|-----------|
| 하부 | 인접 D 650 | 715 | 700 | 600 |
| 하부 | 인접 D 700 | 765 | 750 | 650 |
| 하부 | 인접 D 750 | 815 | 800 | 700 |
| 상부 | 모듈 320 | 395 | 380 | 280 |

- **목대 15 는 뺀다** — 멍판은 목대 앞에서 끝난다. 목대는 도어 경첩이 물리는
  구조재이고 이미 따로 발주된다. 안 빼면 15 과다 재단
- **마감재 60 은 안 뺀다** — 마감재는 멍판을 대체하지 않고 그 **위에** 붙는다
  (§3.3.1). 빼면 마감재가 뜬다

멍장 하나가 내는 정면 부재는 넷이다: `도어` · `멍가림판` · `경첩목대` · `멍판 마감재`.

### 3.6 상부장 멍장 — 2026-09-01 개정 (W12-54)
- 물끊기 없음 (상판이 없다)
- `멍 W = 모듈(몸통 D + 도어 두께) + 마감재 + 목대 15`
- 관례값: **320 + 60 + 15 = 395** (마감재 자리 60 — 부재는 하부와 같이 100 재단)
  (실제로는 D295 + 도어 18 = 313이나, 여유분과 편의를 위해 320으로 계산)
- 확정 예시: `1800 = EP 20 + 890(445×2) + 멍장 840(멍 395 + 도어 445) + 여유 50`

> ⚠ 구버전 `320 + 60 = 380` 폐기 — 멍장 830 → **840**.

### 3.7 인접 라인 시작 위치
인접 라인(멍장이 없는 라인)의 첫 모듈은 코너에서
`멍장 라인 상판 깊이 − 10(물끊기) + 마감재(60)` 지점부터 시작한다.

> **목대 15 는 안 붙는다** (W12-54). 목대는 멍장 도어 경첩을 달기 위한 것이라
> 인접 라인이 시작하는 자리와는 무관하다. 멍(§3.3)과 식이 갈라지는 유일한 지점이다.

```
예: 멍장이 secondary에 있고 secondaryD = 650
→ prime 시작 offset = 650 − 10 + 60 = 700
→ prime 분배 예산 = primeW − 700
```

### 3.8 기타 속성 (기존 유지)
| 항목 | 값 | 비고 |
|------|-----|------|
| 이름 | `LT망장` | type: storage (코드 호환용 명칭 유지) |
| H (높이) | = 하부 높이 - 상판 두께 - 다리 높이 | 자동 계산 |
| D (깊이) | = 소속 라인 깊이 | |
| 고정 여부 | `isFixed: true` | 자동계산에서 제거/이동 불가 (치수는 §3.3~3.4로 재계산) |
| orientation | 소속 Line 표시 | 3D 회전 표현용 |

> ⚠️ 구버전 규칙 폐기: "멍장 W = 인접 Line의 깊이(D)" 및 "상부 멍장 W = upperPrimeD(295)"는
> 2026-07-17 확정 규칙(§3.3~3.6)으로 대체되었다. `isDrawer: true` 기본도 폐기 — 내부는 선반 기본(§3.5).

## 4. 모듈 회전 규칙 (핵심)

> **코너에서 분기되는 모듈은 도어가 prime line을 향하도록 회전 배치한다.**

### 4.1 원칙
```
┌──────────────────┐
│   Prime Line     │ ← 도어가 이쪽을 향함
│   (기준벽)       │
└──────┬───────────┘
       │ 코너
┌──────┴───────────┐
│   멍장 (Blind)   │ ← 코너 오버랩 영역
├──────────────────┤
│   Secondary 모듈  │ ← 도어 방향: prime line 쪽 (↑)
│   Secondary 모듈  │ ← 도어 방향: prime line 쪽 (↑)
│   ...            │
└──────────────────┘
```

### 4.2 상세 규칙

| 항목 | 설명 |
|------|------|
| Secondary 모듈 도어 방향 | Prime Line 방향으로 회전 |
| Tertiary 모듈 도어 방향 | Secondary Line 방향으로 회전 (= Prime과 평행) |
| 멍장 도어 | 각 Line의 교차 방향으로 개방 |
| 3D 렌더링 | `orientation` 속성으로 회전 각도 결정 |

### 4.3 3D 플래너 적용
- `orientation: 'secondary'` → 모듈을 90° 회전하여 secondary line 방향 배치
- `orientation: 'tertiary'` → 모듈을 tertiary line 방향으로 배치
- 도어 생성 면(front face)은 항상 prime line을 향함

## 5. ㄷ자형 Tertiary Line 추가 규칙

### 5.1 Tertiary 시작 방향 (`tertiaryStartFrom`)

| 값 | 의미 | 멍장 위치 |
|----|------|----------|
| `'secondary'` | Secondary Line 끝에서 분기 | Secondary 마지막 모듈을 멍장으로 변환 |
| `'prime'` | Prime Line 반대쪽 끝에서 분기 | Prime 반대쪽 끝에 멍장 추가 |

### 5.2 코너 2개 처리
```
ㄷ자형 (U) 구조:

   ┌── Tertiary Line ──┐
   │                    │ 코너2
   ├── Secondary Line ──┤
   │ 코너1              │
   └── Prime Line ──────┘
```

- **코너1**: Prime ↔ Secondary 교차 → 멍장1
- **코너2**: Secondary ↔ Tertiary 교차 → 멍장2
