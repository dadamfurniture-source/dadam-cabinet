## 1.3 통 내부 구조 표현 — 칸 사각형 목록 (2026-09-17)

정본은 `js/detaildesign/bom-wardrobe-rules.js` (전역 `DadamWardrobeRules` · Node `require`).
BOM·플래너·브리지가 같은 파일을 읽는다 — 서랍 규칙(`bom-drawer-rules.js`)과 같은 자리다.

**왜 칸 목록인가.** 기존 모델은 통 하나에 `moduleType` + 선반수·서랍수를 평면 필드로 달았다.
그 그릇에는 "좌우 반 분할" 도 "하부만 옆 분할" 도 들어가지 않는다. 통 안을 사각형 목록으로 잡으면 둘 다 담긴다.
**칸막이는 저장하지 않는다** — 칸 경계에서 도출한다. 따로 저장하면 칸과 어긋난 상태가 저장될 수 있다.

### 통 하나는 몸통 여럿이다 (2026-09-17 확정)

통(bay) 하나가 캐비닛 하나인 것이 **아니다.**

| 구성 | 몸통 |
|------|------|
| 2단 (위·아래 짧은옷, 선반형, 상단옷봉+하부옆분할) | **하부장 + 상부장 두 벌** — 사이는 칸막이 한 장이 아니라 하부 천판 + 상부 지판 |
| 통장 (긴옷, 반 분할) | 한 벌 |
| 외부 서랍이 있으면 | 맨 아래에 **서랍 몸통 한 벌 더** (§7 별도 제작) |

높이 합은 몸통높이와 정확히 같고, 몫대로 나눈 뒤 **맨 위가 나머지를 먹는다** (`splitStack`).
`layoutWardrobeModule` 이 `carcasses[]` 로 낸다 — 캐비닛만 골라 보려면 `cabinetsOf(layout)`.
칸·칸막이·선반·옷봉의 y 는 **통 좌표**(몸통 바닥 = 좌대 위)이고 각 부재는 `carcass` 로 자기 몸통을 가리킨다.
기존 BOM(`extractWardrobe` 의 `isDivided` 갈래)이 이미 상·하 두 벌로 내고 있었다 — 규칙을 그쪽에 맞췄다.

**서랍은 어느 구조에든 더할 수 있다.** 긴옷(`minDrawers: 1`)은 **최소 1단**이라 0 을 주면 1 로 올리고 경고한다.

```
칸  { x0, y0, w, h, kind: 'rod'|'shelf'|'open', shelves, rods, label }
```

좌표는 **내경 기준**이다. x 는 좌측 측판 안쪽 면에서 오른쪽으로, y 는 **지판 윗면에서 위로**
(플래너 `shelves` 와 같은 방향).

| 값 | 식 |
|----|-----|
| 내경 폭 Wi | W − 2 × T |
| 내경 높이 Hi | (몸통높이 − 외부서랍 높이) − 2 × T |

세로로 반 가를 때 두 칸은 **같은 폭**이다 (`floor((Wi − T) / 2)`). 남는 1mm 는 조립 여유로 둔다 —
나머지를 한쪽에 몰면 427·428 로 갈려 선반·옷봉이 두 가지 치수가 되고 통이 비뚤어 보인다.
위아래로 가를 때는 반대로 **위 칸이 나머지를 먹는다** — 높이는 부재 치수를 바꾸지 않기 때문이다.

### 칸에서 나오는 부재

| 부재 | 자재 | 가로 | 세로 | 관례 |
|------|------|------|------|------|
| 세로칸막이 | PB 15T | D − 18 | 칸 높이 | 측판과 같다 (가로 = 깊이) |
| 중간칸막이 | PB 15T | 칸 폭 | D − 18 | 천지판과 같다 (§11) |
| 선반 | PB 15T | 칸 폭 | D − 18 − 70 | §6 선반 깊이 |

세로 칸막이는 **그 칸 높이만** 차지한다 — 4번 통처럼 하부만 갈린 통에서 판이 위까지 올라가면 안 된다.
같은 자리에 칸이 여럿 걸리면 판은 **한 장**이다 (span 을 합친다).

### 옷봉 — 2026-09-17 새로 낸다

옷봉은 그때까지 **도면에만** 있었다 (`ROD_OFFSET 75` 는 그림 상수였고, 자재·철물 어디에도 없어 발주에서 빠졌다).
이제 철물로 낸다.

| 항목 | 값 |
|------|-----|
| 파이프 | **크롬 25파이** (`ROD_SPEC` · 지름 `ROD_DIAMETER` 25) |
| 파이프 길이 | **칸 내경 폭 − 5** — 양쪽 소켓 자리 (`ROD_LENGTH_MINUS`) |
| 소켓 | **원형소켓**, 옷봉 1개당 **2EA** (`ROD_SOCKET_NAME` · `ROD_SOCKETS_PER_ROD`) |
| 위치 | 칸 상단에서 **75** 아래 (§5 `ROD_OFFSET`) |

수량은 칸마다 센다 — 반 분할 통은 봉이 둘이고 길이도 각 칸 폭에서 나온다. 길이가 다르면 BOM 줄을 나눈다.

칸 구조(`mod.wardrobe`)가 없는 옛 설계도 같은 규격으로 낸다 (`extractWardrobeRods`):
긴옷(`long`)은 옷봉 1개 자동, 나머지는 `rodCountUpper + rodCountLower`, 길이는 `(통 폭 − 2×T) − 5`.

## 2. 높이 계산

```
유효높이(bodyH) = 전체높이(H) - 좌대(60) - 상몰딩(20)
상부장 높이(halfH) = floor(유효높이 / 2)
하부장 높이(halfH) = floor(유효높이 / 2)
```

## 6. 선반 깊이·위치 계산

### 선반 깊이
```
선반 깊이 = 천저판 깊이 - 70
         = (modD - 18) - 70
         = modD - 88
```
- 천저판: 사쿠리 반영으로 modD - 18
- 선반: 천저판보다 70mm 짧게 (전면 여유)

### 선반 위치

### 일반 선반 (짧은옷/선반형)
```
usableH = moduleH - 천판(15) - 지판(15) - 선반갯수 * 15
spacing = usableH / (선반갯수 + 1)
```

## 7. 서랍 규칙

## 8. 선반형 모듈 배타적 규칙

선반형(shelf)에서 **선반과 옷봉은 배타적**:
- 상부장: 선반 추가 시 → 옷봉 자동 제거 / 옷봉 추가 시 → 선반 자동 제거
- 하부장: (선반 또는 서랍) 추가 시 → 옷봉 자동 제거 / 옷봉 추가 시 → 선반+서랍 자동 제거
- 옷봉은 최대 1개

## 9. 자동계산 (runWardrobeAutoCalc)

### 일반 모드 (bar/cchannel/push 핸들)

1. 유효공간에 대해 `distributeModules()` 호출
2. 600mm 기준으로 2D/1D 판별
3. 모듈 타입 자동 할당 (getModuleTypeDefaults):

| 구성 | 모듈 배치 |
|------|----------|
| 2통 (2D, 2D) | 짧은옷, 긴옷 |
| 3통 (2D, 2D, 2D) | 짧은옷, 짧은옷, 긴옷 |
| 4통 (2D, 2D, 2D, 2D) | 짧은옷, 짧은옷, 긴옷, 선반형 |
| 2D+1D (2+1) | 짧은옷, 긴옷, [1D=선반형] |
| 3D+1D (3+1) | 짧은옷, 짧은옷, 긴옷, [1D=선반형] |
| 1D만 | 선반형 |

### 스마트바 모드

1. 총 도어 수 = round(effectiveW / 480)
2. 2D 우선: `modules2D = floor(totalDoors / 2)`, `modules1D = totalDoors % 2`
3. 스마트바 총 너비 = totalModules * 30
4. 도어 공간 균등 배분: `doorWidth = floor((effectiveW - smartbarTotal) / totalDoors)`
5. 모듈 너비: 2D = `doorWidth * 2 + 30`, 1D = `doorWidth + 30`
6. 시공 여유 허용: 10mm

### EP (마감재)

#### 공통 규칙
- **세로 고정**: 모든 몰딩 EP = **2440mm**
- **초과 규칙**: 실제 길이가 2440 초과 시 → 2440mm **2장**

#### 상몰딩
- **moldingH >= 60**: 상몰딩 산출 (MDF 18T, moldingH × 2440)
- **moldingH < 60**: 무몰딩 → 상몰딩 미산출
- totalW > 2440 → 2장

#### 좌우 몰딩
