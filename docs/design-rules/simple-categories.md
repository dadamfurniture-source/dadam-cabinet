## 2. 공유 스펙 (DEFAULT_SPECS)

모든 간단 카테고리는 같은 DEFAULT_SPECS를 상속:
- 상부장 높이: 720mm
- 하부장 높이: 870mm
- 상몰딩: 60mm
- 다리발: 150mm
- 마감: 좌/우 모두 Filler 60mm

## 3. 워크스페이스 구조

sink-style 범용 워크스페이스:

- **하부장 영역** (pos: 'lower')
- 각각 독립적 유효공간 관리
- `distributeModules()` 공통 알고리즘으로 자동계산

## 4. 모듈 추가 기본값

### 상부장/하부장 모듈 추가 시
```javascript
{
  w: 600,
  h: type === 'upper' ? (upperH - 20) : (lowerH - legH),
  d: type === 'upper' ? 295 : 550,
  isDrawer: false,
  isEL: false,
  isFixed: false,
}
```

### 키큰장(TL) 추가 시
```javascript
{
  w: 600,
  h: spaceH - moldingH - 60,
  d: 550,
  isDrawer: false,
  isEL: false,
  isFixed: false,
  doorCount: 1,
  elCount: 0,
}
```

## 6. BOM 규칙 (B3, `extractors.js extractSimpleBox`)

> 코드 위치: `js/detaildesign/extractors.js` `BOM_SIMPLE_CATEGORY_RULES` (카테고리 상수표) · `MaterialExtractor.extractSimpleBox`
> · `HardwareExtractor` 의 `simpleRules` 가지. 골든: `test-utils/bom-golden/{shoerack,vanity,storage,warehouse}.golden.json`
> (`__tests__/bom-golden-simple.test.js`). 계획: `docs/01-plan/detail-bom-deepening.plan.md` §5 B3.

네 카테고리는 §3 대로 싱크대와 **같은 범용 워크스페이스**(상부 + 하부 + 키큰장)를 쓰고 §2 의 DEFAULT_SPECS 를 상속하므로,
몸통 부재표는 **싱크대 규칙(`bom-protocol.md` §3-1 · `sink.md` §5.1 키큰장 단)을 준용**한다. 추출기는 하나이고 카테고리 차이는
아래 상수뿐이다. 싱크대에만 있는 것 — 개수대·쿡탑·후드 가지, 상판, 코너 마감 — 은 내지 않는다.

`categoryId` 는 `data-constants.js CATEGORIES` 의 id 그대로다: `shoerack` · `vanity` · `storage` · `warehouse`.
플래너 프리셋 이름 `shoe`(`ui-step1.js fullHeightPresets`, `planner-engine.js` section) 는 품목 id 가 아니다.

### 6.0 카테고리 상수 (`BOM_SIMPLE_CATEGORY_RULES`)

| categoryId | label | 하부 깊이 폴백 `defaultD` | 상부 깊이 폴백 `upperD` | 선반 기본 개수 규칙 `shelfSpace` |
|------------|-------|------|------|------|
| shoerack | 신발장 | 350 (§1) | **350** (2026-10-28 사장님 — 하부와 같은 깊이, 예전 295) | 상부 2 · 그 밖 **칸 간격 150~300** — `planner-engine.js calcDefaultShelves` 의 `SHELF_SPACE_MIN/MAX_SHOE` 와 같은 수 |
| vanity | 화장대 | 500 (§1) | 295 | 상부 2 · 그 밖 칸 간격 300~450 (`SHELF_SPACE_MIN/MAX`) |
| storage | 수납장 | 400 (§1) | 295 | 상부 2 · 그 밖 칸 간격 300~450 |
| warehouse | 창고장 | 450 (§1) | 295 | 상부 2 · 그 밖 칸 간격 300~450 |
| tvcabinet | TV장 | 400 (§1) | 295 | 수납장 준용 [확인 필요] — 상부 2 · 그 밖 칸 간격 300~450 |

> 2026-10-13 사장님 확정 — 선반 기본 개수는 **플래너 규칙과 같다**(예전: 신발장 180~350, 나머지는 싱크 규칙 하부 1 · 키큰장 1 을 빌림).

- 깊이: `mod.d` → `item.d` → `defaultD` (상부는 `mod.d` → 295). 싱크대의 550 고정 폴백을 타지 않는다 — 신발장 350 에 550 짜리 측판이 나가면 안 된다.
- 선반 수 (`bomSimpleShelfQtyOf`): `mod.shelfCount` 가 숫자면 **그대로** (0 이면 없음, 오픈 칸이라도 지정값이 있으면 낸다 — 신발장 "오픈선반").
  없으면 서랍·EL·오픈(`isOpen` 또는 `doorCount 0`) 은 0, 상부장은 2, 그 밖은 칸 간격 규칙 + 비고 "선반 수 미지정 → …".
  칸 간격: `n = floor(H/min) − 1`, `H/(n+1) > max` 이면 `n = ceil(H/max) − 1` (신발장 708 → 3, 2190 → 13 · 일반 708 → 1, 2190 → 6).
- 도어 수 (`bomSimpleDoorCountOf`): `mod.doorCount` 가 숫자면 그대로(0 존중), `isOpen` 은 0, 없으면 **한 장 최대 600** `ceil(W/600)` (플래너 `DOOR_W_MAX` 와 같다,
  2026-10-13 확정 — 예전 붙박이장 규칙 round(W/450)). 상세설계 화면의 `addStorageModule`/`addModuleAtGap` 은 doorCount 를 안 넣으므로 이 기본값을 자주 탄다.
- 선반 브라켓·경첩·손잡이는 **자재 행과 같은 함수**로 센다 (`bomSimpleShelfQtyOf` · `bomSimpleHingeDoorsOf`) — 골든 시험이 대조한다.

**서랍장 (`isDrawer`)** — 2026-10-22 사장님 카드 "싱크 규칙으로 통일": 전면·목찬넬·박스 모두 **싱크 하부장 서랍 규칙 그대로**
(`drawerLayoutOf` → `addDrawerModuleParts`, `bom-drawer-rules.js`). 전면 합 = 몸통 H − 목찬넬 30 × 개수 (doorCount 가 있으면 [도어, 서랍×n],
없으면 서랍만), 중간 목찬넬 ㄴ자(전면판 72 · 지면판 40 × W)는 모듈 부재, 상단은 EP, 측판 비고에 따내기(목찬넬 손잡이일 때).
박스는 존에 맞는 크기(대 180 · 중 120 · 소 75 — 2026-10-24 소 60 → 75, 맨 위 서랍 존은 앞 밴드 밑부터), 레일 = 깊이 − 50 이하 최대 규격 (D350 → 300 · D400 → 350 · D450 → 400 · D500 → 450 · D550 → 500).
예전 옛 식(서랍도어 220 피치 · 1개면 250 · 남는 높이 아래 여닫이 · 목찬넬 120×W 한 장)은 전면 합이 몸통보다 50 짧아 조립 자리를 정할 수 없어 버렸다.
> 찬넬(알루미늄) 손잡이 서랍장: 전면 재단은 같은 규칙, **측판 따내기 비고와 중간 목찬넬 ㄴ자 행은 없다** (싱크 서랍장도 같다) — 2026-10-22 사장님 "도어는 재단 규칙이 같음. 그러나 따내기, ㄴ자 목찬넬은 없음".

### 6.3 키큰장 (`type:'tall'`) — `sink.md` §5.1 단 부재표 그대로 (`addTallTierParts`)

통짜(`heightParts` 없음)·하부단·중간단·상부단 판별, 도어 H(목찬넬 단 H−30 / 푸쉬 단 H−4), 좌대 상자(앞뒤 W · 측·보강 D − 80)·상몰딩·목찬넬이
싱크대 키큰장과 같다. 다른 것은 **선반 기본값**뿐 — `shelfCount` 가 없으면 §6.0 규칙(상부 2 · 칸 간격 신발장 150~300 · 일반 300~450).
라인 폭(걸레받이·목찬넬)과 다리발에서 키큰장 단은 뺀다 — 좌대가 받친다.

## 7. 신발장 — 띄움 시공 · 상판 · 하부 높이 (2026-10-28 사장님, 간편 플래너 신발장 모듈)

> 사장님: "신발장은 바닥에서 띄움시공이 있어서, 좌대나 다리발이 없는 경우가 있음. 위에 상판이 있는 경우에는 기본을 18T MDF가 올라감."
> 질문 답: 띄움 기본 200 · 신발장 하부장 기본 높이 = 바닥~윗면 1000 · 가림판은 "걸레받이 사이즈로 가되, 신발장 몸통 뒷쪽에 맞춤,
> 그리고 좌우에 마감재도 들어가야함: 높이 = 띄움 높이 + 40, 깊이 = 신발장 몸통 깊이 + 20(현장재단 여유), 18T (MDF, 도어재질)" ·
> 벽 고정 목대는 상부장처럼 — "하부장도 사쿠리형으로 변경" · 상판 깊이 "380 = 몸통 + 앞 자리" · 상부장 깊이 350 (하부와 같게).
>
> 같은 날 좌우 고침: "신발장 좌우 끝 몸통에는 좌우 몰딩, 혹은 쫄(18T*60*높이) 혹은 EP가 들어감, 몰딩 내부에 들어가거나, 몰딩 뒷쪽으로 들어감.
> 정확히는 몸통 바깥쪽에서 결합되어 들어감." · "쫄 일 때 −35 — 쫄 60 중에 25 정도는 도어 앞선에 맞춰야 해서 몸통보다 앞으로 튀어나옴" ·
> "몰딩 18T + 몰딩쫄(30*18T) = 최소 36, 도어 앞선 맞춤 → 몸통 안 11, 가림판은 여유 5mm 를 감안해 몸통에서 −5" ·
> 질문 답: EP 끝은 가림판 없음 · 마감재 없는 끝은 배치 공간 깊이 그대로 · 띄움이면 쫄은 바닥까지. 다음 날(10-29): "쫄일 경우 −40 으로 하자. 여유 5 확보를 위해".
