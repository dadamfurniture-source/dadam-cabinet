멍장 규칙 확정 — "멍"은 인접 라인에 가려지는 구간이다

2026-07-17 답변으로 6개 질문이 모두 확정되어 docs/design-rules/corner.md에 반영 완료. 핵심: 멍장 W는 독립 규격이 아니라 라인 전체 도어 균등 분배의 결과다.

확정 2026-07-17 기준 예시 secondary 1970 · prime 상판깊이 650 규칙 반영 corner.md §3 (W10-0 완료)

01무엇을 잘못 이해했었나

이전 이해 — 틀림

  • 멍장 W = 파생값 (primeD + 40 = 590)
  • +40 = 도어 간섭 여유라고 추측
  • 멍장 전체가 "코너 점유 박스"이고 도어 구성은 별도 규칙 대기

정정된 이해

  • 멍장 W = 기본 규격 1000~1200 (파생값 아님)
  • 멍장 내부가 두 구간으로 나뉨: 멍(가려짐) + 도어(열림)
  • 멍 = prime 라인에 의해 가려지는 부분 — 여기가 파생값
  • 도어는 가려지지 않은 나머지 폭에 한 짝만 달림

즉, 파생 공식이 적용되는 대상이 멍장 전체 폭이 아니라 멍장 안의 "멍" 구간이었습니다. 멍장 폭은 규격(1000~1200)에서 출발하고, 멍의 크기가 prime 라인의 깊이에서 계산되며, 도어 폭은 그 차이로 결정됩니다.

02멍의 공식 — 650 − 10 + 60 = 700

알려주신 예시를 단계별로 분해한 것입니다.

멍 W = prime 상판 깊이 − 10 + 몰딩
     = 650 − 10(물끊기 여유) + 60(몰딩) = 700

도어 W = 멍장 W − 멍 W = 1000 − 700 = 300 (도어 1짝)

03평면으로 본 멍장 — 왜 가려지는가

멍장은 secondary 벽을 따라 서 있고, prime 라인이 그 앞을 가로질러 지나간다.

이 그림이 맞다면, −10의 위치도 이해됩니다: prime 도어면은 상판 끝(650)에서 10 들어간 640에 있고, 몰딩은 그 도어면(640)에서 시작해 60을 더해 700에서 끝납니다. 몰딩 끝(700)이 곧 멍장 도어의 시작점이며, 상판 끝(650)에서 떨어지는 물은 도어(700부터)가 아니라 몰딩 위(640~700 구간)에 떨어집니다.

04정면으로 본 멍장

확정 멍 구간 정면은 2.7T MDF로 가리고, 내부는 카카스 전체가 하나의 수납 공간(하부장 선반 기본)으로 도어를 통해 접근한다. 필요 시 회전 선반 등 하드웨어 장착 가능. (§04 정면도의 좌측 구간 = MDF 가림판, BOM 부재로 산출)

05확정 공식 — 도어 균등 분배가 멍장 W를 결정한다 확정

멍장 W는 입력값이 아니다. 라인 원장(ledger)에서 남는 도어 폭이 멍장 도어가 된다.

멍 W      = 인접 상판깊이 − 10(물끊기) + 몰딩(60)  // 하부장. 상부장: 320 + 60 = 380 (물끊기 없음)
도어 가용폭 = 라인 W − EP(20) − 벽 여유(50) − 멍 W
도어 W     = 도어 가용폭 ÷ 도어 수 (라인 전체 균등, 최소 350)
멍장 W     = 멍 + 도어

확정 deriveCorner()

function deriveCorner(specs, blindLine /* 'prime'|'secondary' — 사용자 결정 */) {
  const molding = specs.finishCornerW || 60;
  const adj     = otherLine(blindLine);                    // 인접 라인

  // ① 멍 — 하부: 인접 상판깊이 − 10 + 몰딩 / 상부: 320 + 몰딩 (물끊기 없음)
  const blindZoneLower = specs[adj].topD - 10 + molding;   // 650−10+60 = 700
  const blindZoneUpper = 320 + molding;                    // = 380 (295+18≈313 → 관례 320)

  // ② 도어 균등 분배 — 라인 원장에서 도어 가용폭 산출
  const avail  = specs[blindLine].w - EP(20) - WALL_GAP(50) - blindZoneLower;
  const nDoors = maxDoorsAtLeast(avail, MIN_DOOR_W /* 350 */);
  const doorW  = avail / nDoors;                           // 1200/3 = 400

  return {
    blind:   { w: blindZoneLower + doorW, doorW, doorCount: 1, blindCover: '2.7T MDF' },
    budgets: { [adj]: specs[adj].w - (specs[blindLine].topD - 10 + molding) },  // prime 시작 offset 차감
  };
}

BOM 관점의 결정적 변화: 멍장에서 산출되는 부재는 ① 도어 400(카카스 폭 1100이 아님), ② 멍 가림판 2.7T MDF (W 700), ③ 카카스(측판/천판/지판/뒷판) 1100 기준, ④ 선반(기본) — 이 조합이 정확한 발주 수량이다.

Q6상부장 멍장 물끊기 없이 멍 = 모듈(몸통D+도어두께) + 몰딩 = 320 + 60 = 380. 실제 295+18=313이나 여유·편의상 320 사용

남은 확인 1건 — 도어 수 결정 규칙 해석 확인

도어 수는 "최소 350을 만족하는 최대 도어 수"로 해석했습니다.

예시 검산: 가용폭 1200 → 1200÷4 = 300 (350 미달, 불가) → 1200÷3 = 400 ✓ — 예시와 일치. 다만 "가능한 큰 도어 우선"(1200÷2 = 600) 같은 다른 규칙일 수도 있으므로, 구현 시 기존 calc-engine 도어 분배 로직과 대조 후 어긋나면 다시 확인드리겠습니다.
