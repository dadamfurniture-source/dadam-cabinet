멍판 마감재 포개기

멍판 마감재(100)는 멍가림판 위에 포개어져야 하는데, 지금 정면·3D는 마감재를 멍가림판 옆 칸으로 그립니다. 그래서 멍가림판이 목대까지 닿지 않고(85mm 짧음) 마감재가 그 옆에 따로 섭니다. BOM 숫자는 맞습니다 — 표현 모델이 틀렸습니다. 원인은 "포개는 부재"를 "나란한 칸"으로 넣은 것이고, 해결은 마감재를 칸에서 빼 덮개로 그리는 것입니다.

02왜 이렇게 됐나

W12-61 에서 마감재를 정면 셀로 넣었습니다 — [blind zoneW−100][blindfin 100][door]. 셀은 모듈 폭을 빈틈없이 나눠 갖는 모델입니다. 두 칸이 같은 자리를 차지할 수 없습니다. 그런데 마감재는 정의상 멍가림판 위에 40 을 물고 올라오는 부재라(재단 100 = 자리 60 + 겹침 40), 나란한 칸으로는 애초에 그릴 수 없었습니다.

// ensureCornerModules (지금)
ws = [zoneW − finW, finW, doorW]     // 멍 칸에서 100 을 떼어 옆에 세움 → 멍판이 100 짧아짐(목대 15 만큼은 도로 남음)

BOM(extractors.js)은 셀을 보지 않고 blindZoneW − 15 와 partW 100 을 따로 내므로 발주는 맞습니다. 틀린 것은 정면도·3D 표현과, 분할 패널에 "멍판 마감재 (파생)" 칸이 하나 더 보이는 것입니다.

03해결안

A · 권장마감재를 칸에서 빼고 덮개(overlay) 로 그린다

셀은 [멍 zoneW][도어] 두 칸으로 돌아갑니다 — 키큰장 멍장(W12-65)과 같은 모양입니다. 멍 칸 안에서 렌더러가 세 부재를 겹쳐 그립니다:

// 멍 구간 좌표 (벽 쪽 0 → 도어 쪽 zoneW), 하부·상부 공통
멍가림판  0 .. zoneW − 15                    2.7T · 맨 뒤
마감재    zoneW − 15 − 100 .. zoneW − 15       18T · 멍판 위(z +2.7)
목대      zoneW − 15 .. zoneW                 그리지 않음(지금처럼) 또는 얇은 띠
// 키큰장: 마감재 없음, 멍가림판 대신 EP 18T 0 .. zoneW − 15

좌표 계산은 planner-engine.js 에 순수 함수 blindFrontLayout(zoneW, {ep}) 하나로 두고 2D·3D·테스트가 같은 값을 씁니다. 멍장이 오른쪽 끝(도어가 먼저)이면 좌우를 뒤집습니다.

✓ 물리와 같은 모델. 키큰장 EP 폭(zoneW − 15)도 같은 함수로 맞아 들어간다. 분할 패널의 파생 칸도 사라진다.

B칸을 넷으로 — [멍 650][마감 100][목대 15][도어]

마감재를 목대 앞에 정확히 놓을 수는 있지만, 멍가림판은 여전히 650 까지만 그려집니다 — 마감재 아래로 뻗는 100 을 칸으로는 표현할 수 없습니다. 목대라는 선택 불가 칸이 패널에 하나 더 생깁니다.

✗ 증상 절반만 고치고 모델은 더 복잡해진다.

바뀌지 않는 것

멍 공식(765) · 멍장 폭 · 도어 폭 · 원장 · BOM 네 부재(도어 · 멍가림판 750 · 경첩목대 · 마감재 100). 그림과 셀 수만 바뀝니다. 골든 스냅샷은 코너를 포함하지 않아 그대로입니다.

04A 안 구현 단계

  1. planner-engine.js — blindFrontLayout(zoneW, opts) 벽 쪽 0 기준으로 { cover:[0, zoneW−15], finish:[zoneW−115, zoneW−15] | null, batten:[zoneW−15, zoneW] }. opts.ep 면 cover 가 EP 이고 finish 는 null. 목대·재단 상수는 MASTER_RULES 에서.
  2. ensureCornerModules — 셀 2칸 하부·상부도 ['blind','door'] / [zoneW, doorW]. m.blind.finish 는 그대로 둔다(종류·재단은 BOM 이 쓴다).
  3. 2D renderModuleFront — 멍 칸 안에 세 겹 멍 칸 rect(멍판 색) 위에 마감재 rect(마감재 색·라벨)를 blindFrontLayout 좌표로 겹쳐 그린다. 도어가 먼저 오는 배치(areaTypes[0]==='door')면 좌우 반전. 멍판 폭은 zoneW−15 로 목대 자리를 비운다.
  4. 3D addFrontPanel 'blind' — 같은 좌표로 세 상자 멍가림판(2.7T, overlayZ) → 마감재(18T, overlayZ+2.7, x 를 멍판 끝에 맞춤). 키큰장은 EP 18T 하나. 메타에 doorSide 를 넘겨 반전을 정한다.
  5. 분할 패널 · 변환기 'blindfin' 옵션 제거. ui-step1 의 멍장 분기는 셀을 안 보므로 변경 없음. 마감재 종류 연동(blindFinishFor)·재계산 훅은 그대로.
  6. 테스트 planner-blind-finish.test.js 의 "세 칸 · 마감재 칸이 도어 바로 옆" 을 "두 칸 · 마감재 덮개가 멍판 끝 100 을 덮고 목대 15 앞에서 끝난다" 로 바꾼다. planner-blind-cell.test.js · planner-corner-blind.test.js 의 셀 수를 2 로. 3D 는 마감재 상자 x 범위가 멍판 상자 안에 있고 z 가 +2.7 임을 잠근다.

규모: 렌더 두 곳 + 셀 정의 한 곳 + 순수 함수 하나. BOM·규칙 문서는 이미 맞아 손대지 않습니다. 캐시 버전은 플래너만 범프(37.9 → 38.0).

05확인 하나

목대 15 를 정면에 표시할까요?

지금은 멍 칸 안에 묻혀 있고 마감재가 그 위를 덮고 있었습니다. A 안에서는 멍판(zoneW−15)과 도어 사이에 15mm 빈 띠가 생깁니다 — 실제로 목대가 있는 자리입니다. 얇은 짙은 띠로 그릴지, 비워 둘지 정해 주세요.

제안 — 짙은 띠로 그린다(3D 는 15T 상자). 경첩이 물리는 자리라는 것이 보이고, 멍판이 거기 "딱 붙는" 것이 드러납니다.
