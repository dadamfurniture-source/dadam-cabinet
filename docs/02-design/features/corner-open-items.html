코너 미결 두 건

코너 구멍(W12-63, PR #561)은 머지됐습니다. 그 작업 범위 밖에 남긴 것이 둘입니다. 하나는 규칙 결정이고(사람이 멍장 자리를 고르는 토글), 하나는 기존 결함입니다 (코너 끝에 마감재를 붙이면 멍장이 부품보다 작아짐). 둘 다 왜 남았는지, 언제 터지는지, 지금 피하는 법과 고치는 법을 적었습니다.

2026-09-09 — 둘 다 해결됐습니다

A 겹친 코너의 멍장 자리 → W12-65 (PR #565): 배치 공간 blindOwner + 구조 단계 ◀ 멍장 위치 ▶ 토글. 트리밍된 코너는 기하가 정하고(W12-63), 겹친 코너만 사람이 고른다.

B 코너 끝 마감재가 멍장 폭을 뺏음 → W12-64 (PR #564): 고정 모듈은 폭을 내놓지 않고, 코너 배치 공간은 마감재 변경 시 자동계산을 다시 돌며, 변환기에 멍장 카카스 ≠ 멍+도어 그물을 넣었다. 코너 끝 마감재는 계속 고를 수 있다(벽 | 여유 50 | 마감재 | 멍장).

02A · 겹친 배치에서는 멍장 자리를 기하로 못 정한다

W12-63 이 "코너 사각형을 가진 라인이 주인" 으로 바꿨습니다. 그 규칙이 답을 못 내는 경우가 하나 남습니다.

지금 코드가 하는 일

// orderCorner (W12-63)
코너 사각형을 한쪽이 확실히 더 가지면   → 그쪽이 주인          트리밍된 배치
반씩 나눠 가지면                       → 회전 규칙으로 폴백    겹친 배치 — 여기가 A
   회전한 다리가 주인 · 둘 다 회전이면 x+y 큰 쪽

폴백은 "결정적이면 된다" 는 용도입니다. 같은 배치를 다시 열어도 같은 답이 나오게 하려는 것이고, 맞는 답을 고르려는 것이 아닙니다. 회전은 도어 방향(= 벽이 어느 쪽인가)이라 주선·차선과 무관하다는 것을 W12-63 에서 확인했습니다.

규칙 문서는 이미 답을 정해 놨다 — 조작이 없다

docs/design-rules/corner.md §3.2  소속 라인 (사용자 결정)
  · 멍장은 prime 또는 secondary 어느 라인에도 배치 가능 — 사용자 결정에 따른다

레거시는 blindLine = 'secondary' 로 고정했고(W10-1), 플래너에는 고를 수단이 없습니다. 예전에 area.blindOwner 를 읽는 가지가 있었지만 쓰지도 저장하지도 않는 값이라 W12-60 에서 죽은 코드로 뺐습니다. 그때 주석에 "토글이 필요해지면 UI·저장과 함께 넣는다" 고 남겨 두었습니다.

고치려면

  1. 저장 배치 공간에 blindOwner 를 둔다 — 그 공간이 이루는 코너에서 멍장을 내가 갖는다는 표시. 겹친 배치에서만 뜻이 있다.
  2. 읽기 orderCorner 의 폴백 앞에서 본다 — 한쪽에 표시가 있으면 그쪽이 주인. 둘 다 있거나 둘 다 없으면 지금 폴백.
  3. UI 구조 단계 배치 공간 패널에 ◀ 멍장 위치 ▶ 한 줄. 코너를 이루는 공간에서만 보이고, 누르면 두 공간의 표시를 맞바꾸고 자동계산을 다시 돈다.
  4. 배치 단계에도 알린다 트리밍 가드(W12-55) 경고문에 "겹친 채 넘어가면 멍장 자리는 구조 단계에서 고르셔야 합니다" 한 줄.

급하지 않은 이유

트리밍을 제대로 하면 기하가 정하고 토글은 필요 없습니다. 그리고 트리밍은 이미 배치 단계가 권하는 동선입니다(W12-55). 토글은 "겹친 채 넘어오는 사람" 을 위한 보조 장치입니다.

03B · 코너 끝 마감재가 멍장 폭을 뺏는다

main 에 원래 있던 결함입니다. W12-61 이후 라인 마감재가 멍판 마감을 정하는 조작이 되어 마주칠 확률이 올라갔습니다.

증상 — 트리밍된 ㄱ자에서 실측 (W12-63 이후)

동작멍장 카카스멍 + 도어차이원장
자동계산 직후1162116200 / 0
주인 라인 코너 쪽 끝에 몰딩11021162−60−50 / 0
주인 라인 반대쪽 끝에 몰딩11021162−60−50 / 0
인접 라인에도 몰딩11021162−60−50 / −50
자동계산 재실행1138113800 / 0

원장은 주인 / 인접. 재계산 뒤 1138 은 맞는 값입니다 — 마감재 60 이 정당하게 도어 몫에서 빠진 결과. 문제는 그 사이의 상태입니다.

왜 이런 일이 생기나 — 네 단계

원장 −50 은 별개의 작은 결함

위 표의 −50 은 redistributeAreaWidths 가 코너 예약(벽 여유 50 · 인접 밀림)을 모르고 모듈을 area.x + 마감폭 부터 다시 깔기 때문입니다. 트리밍된 배치에서는 50 짜리라 눈에 잘 안 띄고, 이것도 재계산으로 복구됩니다. 같은 수정에 얹어 가면 됩니다.

왜 위험한가

자가 복구는 사람이 자동계산을 다시 누를 때만 일어납니다. 마감재를 고르고 바로 [디테일 단계] 나 BOM 산출로 넘어가는 것이 자연스러운 동선인데, 그 길에는 방어막이 없습니다. 깨진 상태로 뽑은 BOM 을 실측한 적이 있습니다 — 카카스 안폭 1026 에 도어 397 + 멍가림판 700 이 들어가야 하는 자재표가 경고 없이 나왔습니다.

고치는 길 — 넷 중 고르거나 겹친다

①setModuleFinish 가 isFixed 호스트를 거부한다

고정 모듈은 폭을 내놓지 않는다. 대신 그 옆 비고정 모듈이 내놓게 하거나, 없으면 토스트로 막는다. 멍장·사람이 고정한 모듈 모두를 지킨다. 가장 작고 정확한 수정.

②변환기에 멍장 정합성 검사를 넣는다

ui-step1 의 if (m.blind) 가지 안에서 m.W === zoneW + doorW 를 확인하고, 어긋나면 "자동계산을 다시 실행하세요" 경고를 낸다. ①을 고쳐도 다음 번 비슷한 실수를 잡는 그물이라 같이 넣는 것이 맞다.

③redistributeAreaWidths 가 코너 예약을 안다

벽 여유 50 과 인접 밀림을 빼고 깐다. 원장 −50 이 사라진다. ①에 얹어 간다.

④코너 쪽 끝에는 마감재를 못 붙이게 막는다 규칙 판단

그쪽은 벽이고 멍장은 이미 벽에서 50 떨어져 있다. 몰딩·휠라는 라인의 바깥 끝을 마감하는 부재다 — 코너 끝에 붙일 이유가 있는지부터 정해야 한다. 막으면 ①의 절반은 자연히 사라지지만, 사람이 고를 수 있던 것을 줄이는 결정이라 제가 정할 일이 아니다.

제안

① + ② + ③ 을 한 PR 로. ④는 규칙 판단이니 답을 주시면 따르고, 안 주시면 지금처럼 붙일 수 있게 둡니다(①이 지키므로 붙여도 멍장은 안 깨집니다).

04순서 제안

  1. B 먼저. 유일하게 잘못된 자재가 실제로 발주되는 경로이고, 경고도 없습니다. 상부·하부·(앞으로) 키큰장 코너 전부에 걸립니다.
  2. A 는 키큰장 코너 작업과 함께. 키큰장끼리 코너는 섹션 신호가 없어 토글이 더 필요해지는데, 그 작업(계획서 §06)에 얹으면 따로 만들 것이 없습니다. 그때까지는 트리밍이 대신합니다.
